# Incident — 15 resume_builds mass-failed with NULL error (2026-05-11)

## Summary
At 2026-05-11 23:34 UTC, 15 in-flight resume builds simultaneously failed with `status='failed'`, `error=NULL`, `iterations=0`, `cost=0`, `latency=0`. All 15 rows share the identical `finalized_at=2026-05-11 23:34:13.070859+00`, coinciding with a Railway worker v8 deploy that sent SIGTERM to the old pod. The worker had no signal handler, so in-flight builds were abandoned and the then-buggy orphan_reaper sweep flipped them without recording a failure reason. The B6 CHECK constraint (PR #127) now prevents NULL-error rows structurally, and the B7 SIGTERM guard (this PR) closes the remaining window by marking in-flight builds before the process exits.

## Root cause
Railway deploys send SIGTERM with a ~10 second grace period before SIGKILL. The `api/worker.py` process had no signal handler registered, so Python's default applied: raise KeyboardInterrupt. In-flight G2 builds (15 `resume_builds` rows in `status='running'`) were abandoned mid-graph. The orphan_reaper sweep (running every 5 minutes) found these rows ~8 minutes later and flipped them to `status='failed'` — but the sweep wrote to a column name that didn't exist (`error_message` instead of `error`), so PostgREST silently dropped the value, leaving `error=NULL`.

The B6 CHECK constraint (`ALTER TABLE resume_builds ADD CONSTRAINT ... CHECK (status != 'failed' OR error IS NOT NULL)`) now makes this regression structurally impossible: any attempt to set `status='failed'` with `error=NULL` will throw a constraint violation. The B6 column fix ensures the sweep writes to the correct `error` column. The B7 SIGTERM guard in `api/worker.py` closes the remaining operational window: before the worker process exits, it sweeps all `status='running'` `resume_builds` and `jobs_runs` rows, flipping them to `failed` with the descriptive error `worker_sigterm_received`.

## Prevention
- B6 CHECK constraint on `resume_builds` (shipped PR #127) — structurally prevents NULL-error failed rows
- B6 orphan_reaper column fix `error_message` -> `error` (shipped PR #127) — ensures sweep writes land
- B7 SIGTERM handler in `api/worker.py` (this PR) — flips in-flight builds before process death
- Recommended ops follow-up: bump Railway pod grace period from 10s to 30s (env var `SIGKILL_GRACE_SECONDS` or Railway service config) to give the sweep more margin
